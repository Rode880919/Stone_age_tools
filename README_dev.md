# sa_pet_assistant 开发者说明

本文面向开发者或维护者，重点说明项目结构、模块职责、当前口径和维护注意事项。

## 1. 项目概览

`sa_pet_assistant` 是一个 `tkinter` GUI 项目，入口为 `main.py`，后端计算逻辑在 `backend/`，前端页面在 `frontend/`。

当前 GUI 包含 5 个标签页：

- `反推计算`
- `成长模拟`
- `转生模拟`
- `融合成蛋`
- `融合蛋喂药`

## 2. 运行方式

直接运行：

```bash
python main.py
```

演示模式：

```bash
python main.py --demo
```

`main.py` 会把项目根目录插入 `sys.path`，保证直接从当前项目目录运行时能正确导入 `backend` 和 `frontend`。

## 术语约定

后续维护时，建议始终按下面这组定义写代码注释、页面文案和文档：

- `成长率`：宠物 `V / S / T / D` 四项成长值
- `VSTD`：四项成长率总和
- `蛋基础成长`：融合后、喂药前的蛋面值
- `孵化后成长` / `孵化后成长档`：`PET_getEvolutionAns()` 输出结果，不含出生后 10 点随机
- `出生后 10 点随机`：出生阶段附加的 10 点随机分配，不属于成长档

当前项目中：

- `反推计算` 处理的是宠物成长率
- `融合成蛋` 同时展示蛋基础成长和孵化后成长
- `融合蛋喂药` 的优化目标是孵化后成长，不是蛋基础成长

## 4. 前端结构

### 4.1 `frontend/app.py`

主窗口与标签页装配点。

职责：

- 创建主窗口
- 配置 notebook
- 组装 5 个页面
- 负责“反推计算”页面的后台线程触发与回调

### 4.2 `frontend/input_panel.py`

“反推计算”输入区。

职责：

- 动态增删等级行
- 校验等级、属性值
- 支持“转生宠物”开关
- 输出排序后的等级数据

### 4.3 `frontend/result_panel.py`

“反推计算”结果区。

职责：

- 展示候选成长率与 `INITNUM`
- 展示进度条
- 展示错误信息与状态信息

### 4.4 `frontend/sim_panel.py`

“成长模拟”页。

职责：

- 输入 `INITNUM`、成长率、模拟次数
- 调用 `simulate_lv140`
- 展示 140 级分位数表

### 4.5 `frontend/trans_panel.py`

“转生模拟”页。

职责：

- 输入宠物成长、MM、等级、转生次数、`转生能力上限`、模拟次数
- 调用转生计算与模拟逻辑
- 展示转生信息与 140 级分位数表

### 4.6 `frontend/fusion_panel.py`

“融合成蛋”页。

职责：

- 读取主宠 / 副宠输入
- 调用 `backend.fusion.calc_fusion_egg_base`
- 展示融合中间步骤
- 展示蛋基础成长与无喂药孵化后成长

### 4.7 `frontend/evolution_panel.py`

“融合蛋喂药”页。

职责：

- 输入蛋基础成长与规则参数
- 选择优化模式
- 调用 `analyze_evolution_feeding`
- 支持候选解回填到自定义喂法
- 支持自定义喂法实时刷新

## 5. 后端结构

### 5.1 `backend/reverse.py`

职责：

- 根据多等级属性数据生成候选成长率组合
- 作为“反推计算”核心候选枚举逻辑

### 5.2 `backend/scorer.py`

职责：

- 对候选成长率进一步评分
- 输出更适合界面排序展示的候选结果

### 5.3 `backend/matrix.py`

职责：

- 提供反推相关矩阵计算辅助

### 5.4 `backend/simulator.py`

职责：

- 普通宠成长模拟
- 转生成长计算与模拟
- Rank / 随机范围相关辅助

### 5.5 `backend/fusion.py`

职责：

- 融合成蛋的确定性基础成长计算
- 在融合结果上继续调用孵化逻辑，得到“无喂药孵化后成长”

当前返回结果包含：

- 主宠修正值
- 副宠修正值与平均值
- 蛋基础成长 `egg_base`
- 蛋基础 `VSTD`
- 孵化后成长 `hatch_alloc`
- 孵化后 `VSTD`

### 5.6 `backend/evolution.py`

职责：

- 融合蛋喂药搜索
- 药值折算
- 孵化成长计算
- 候选解排序
- 自定义方案复算

这是当前“融合蛋喂药”功能的核心模块。

## 6. 当前计算口径

### 6.1 融合成蛋页

当前口径明确：

- 包含融合后的确定性蛋基础成长
- 包含“无喂药”情况下按 `PET_getEvolutionAns()` 计算的孵化后成长
- 不包含蛋面 `+-2` 随机
- 不包含出生后的 10 点随机加点

### 6.2 融合蛋喂药页

当前优化目标是：

- 孵化后成长档
- 不包含出生后 10 点随机加点

不是：

- 蛋面基础成长本身

### 6.3 取整策略

项目当前实现强调按源码步骤保留中间取整，不建议把多个步骤合并后再算。

特别要注意的取整点：

- 药值折算
- 折算总和压缩
- 副宠平均
- 主宠 / 副宠贡献
- 孵化时按比例重新分配
- 最终总和压缩

### 6.4 `incubate_alloc()` 逻辑

当前实现中，`total > 0` 时就会进入孵化分配分支，即使 `total1 == 0` 也不额外拦截。这是为贴近 `gmsv` 当前 `PET_getEvolutionAns()` 的逻辑。

## 7. 融合蛋喂药页面的优化模式

当前提供两种模式：

1. 线性目标
   - 使用 `xV / xS / xT / xD` 作为权重
   - 目标值为四项成长的线性组合
2. 主目标 + 次目标
   - 先比较主目标单项
   - 并列时再比较次目标单项

更多说明见：

- [fusion_opt.md](./fusion_opt.md)

## 8. 参数与限制

### 8.1 成长模拟 / 转生模拟

- 模拟次数范围：`1~50000`

### 8.2 转生模拟

默认`转生能力上限`：

- 第 1 次转生：`150`
- 第 2 次转生：`200`

但界面允许手工改写。

### 8.3 融合蛋喂药

当前固定约束：

- 必须喂满 `40` 颗
- 当前不处理超时衰减

## 9. 打包

项目内自带脚本：

```bash
bash build.sh
```

当前脚本会：

- 检查 `numpy` 与 `tkinter`
- 使用 `PyInstaller --onefile --windowed`
- 将 `backend` 和 `frontend` 一并打包

默认输出：

```text
dist/sa_pet_assistant.exe
```

项目内还保留以下 spec：

- `sa_pet_assistant.spec`
- `宠物工具箱.spec`（旧名称兼容文件）

## 10. 维护建议

### 10.1 修改口径时

如果你修改了以下任何内容，建议同步更新文档：

- 界面字段名
- 默认参数
- Rank 说明
- 融合 / 孵化 / 喂药取整口径
- 结果字段含义

至少需要同步：

- `README_user.md`
- `README_dev.md`
- `fusion_opt.md`

### 10.2 修改前端时

当前项目的 UI 是纯 `tkinter/ttk`，没有额外主题系统。维护时建议：

- 优先保持输入网格对齐
- 不要因为局部拉伸破坏整页对齐
- 先保证信息可读，再考虑压缩高度

### 10.3 修改后端时

如果变更和 `gmsv` 对齐有关，建议至少自查：

- 是否改变了中间取整时机
- 是否改变了单项 / 总和上限触发顺序
- 是否把“蛋基础成长”和“孵化后成长”混在一起
- 是否误把出生后的 10 点随机混入成长档优化目标
